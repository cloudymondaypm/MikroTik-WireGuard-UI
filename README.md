# MikroTik WireGuard UI

A WireGuard Easy-style web interface that **does not run its own WireGuard server**. It manages the peers of an existing WireGuard interface on a MikroTik RouterOS v7 router through the RouterOS REST API.

## What it does

- Reads the live WireGuard peer list from MikroTik.
- Creates a client key pair in the web app, adds only the client's **public key** to MikroTik, and stores the client private key encrypted in the app data volume.
- Enables/disables MikroTik peers.
- Removes peers from MikroTik.
- Generates a WireGuard client QR code and `.conf` file for clients created by this app.
- Shows MikroTik peers created elsewhere. Those peers can still be enabled/disabled/deleted, but QR/config export is disabled because their client private key is not available to the app.
- Exports/restores app-managed client metadata and keys through the Backup/Restore buttons.

## Architecture

Browser -> Next.js/React UI -> FastAPI -> MikroTik RouterOS REST API -> existing MikroTik WireGuard interface

The application never creates a Linux WireGuard interface and never forwards VPN traffic. MikroTik remains the WireGuard server/router.

## MikroTik prerequisites

RouterOS v7 is required for the REST API. Prefer HTTPS (`www-ssl`) rather than plain HTTP.

Example RouterOS setup outline (adjust IP ranges and service restrictions for your network):

```routeros
# Existing WireGuard interface, if you do not already have one
/interface/wireguard/add name=wireguard1 listen-port=13231
/ip/address/add address=10.120.0.1/24 interface=wireguard1

# Dedicated service user. Give only the permissions needed in your environment.
/user/group/add name=wg-ui policy=read,write,api
/user/add name=wg-ui group=wg-ui password="USE-A-STRONG-PASSWORD"

# REST is served by www-ssl. Configure a certificate before production use.
/ip/service/enable www-ssl
```

Restrict the RouterOS `www-ssl` service and/or firewall so only the web-app host or management subnet can reach it.

## Deploy with Docker Compose

```bash
cp .env.example .env
nano .env

docker compose up -d --build
```

Open (the default Compose mapping publishes the UI on TCP 80):

```text
http://YOUR-SERVER-IP
```

Default username in the example is `admin`; use the password you placed in `.env`.

## Important environment values

- `MIKROTIK_HOST`: MikroTik management IP or hostname. This deployment uses `10.10.1.10`.
- `MIKROTIK_REST_PORT`: dedicated RouterOS REST port. This deployment uses HTTPS on `8443`, restricted to the application container.
- `MIKROTIK_WG_INTERFACE`: exact RouterOS WireGuard interface name.
- `CLIENT_POOL_CIDR`: address pool used for new road-warrior clients. This deployment uses `10.10.16.0/24`; `10.10.16.1` is reserved for MikroTik and clients start at `.2`.
- `WG_ENDPOINT_HOST`: public IP or DNS name clients use to reach MikroTik.
- `WG_CLIENT_ALLOWED_IPS`: what client traffic goes into the tunnel. This deployment uses split-tunnel IPv4 routing, `10.10.0.0/16`; only local 10.10.x.x destinations traverse WireGuard and ordinary internet traffic uses the client's own connection. DNS remains `10.10.1.15` through the tunnel for internal hostnames. Previously imported profiles must be re-imported or edited on each device.
- `WG_CLIENT_DNS`: DNS sent in generated client configurations.

## Security notes

- `Backup` contains WireGuard client private keys. Treat the file like credentials.
- Client private keys generated by this app are encrypted at rest with a Fernet key stored in the Docker data volume.
- Do not expose the RouterOS REST API directly to the public Internet.
- For production, use a reverse proxy with HTTPS in front of the UI and set `COOKIE_SECURE=true`.
- Replace `JWT_SECRET`, `APP_PASSWORD`, and the MikroTik API credentials before use.

## UI behavior

The main screen intentionally mirrors the layout of the supplied WireGuard interface reference: WireGuard header, theme/logout area, Clients card, Restore/Backup/New controls, client rows, red enable switch, QR, download, and delete actions.
